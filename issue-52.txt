# Add standalone time-to-liquidation tab

## Objective

Add a standalone **Time to liquidation** tab to the Streamlit LMT calibration dashboard.

The tab should provide a clean asset-side liquidity view showing how quickly the current portfolio can raise cash under benchmark redemption shocks, participation-rate assumptions and liquidity-haircut assumptions.

This first version should **not** use the dashboard’s existing market scenarios, NAV shock scenarios, liquidation-cost scenarios, stochastic investor-redemption paths or LMT threshold settings. It should be a simplified TTL sensitivity view inspired by time-to-liquidation style stress testing.

The goal is clarity:
- show the current asset mix;
- show cumulative liquidation capacity over time;
- show how TTL changes under participation-rate and liquidity-haircut sensitivities;
- avoid mixing this with the existing 12-month redemption/LMT engine.

---

The sample portfolio has been cleaned to remove repo-driven liquidity cushions. Reverse repo and repo financing rows should no longer be part of the `lux_dynamic_allocation` sample.

## Methodology scope

Implement a simple asset-side time-to-liquidation calculation.

### In scope

The TTL tab should use:
- current portfolio positions;
- current market values;
- base liquidity capacity rates;
- benchmark redemption shocks as % of NAV;
- benchmark participation rates;
- benchmark liquidity haircuts;
- settlement days if already available in the position data.

### Out of scope

Do **not** implement:
- CSSF macroeconomic redemption-flow regression;
- the dashboard’s existing historical market scenarios;
- scenario-specific NAV reductions;
- scenario-specific liquidation-cost assumptions;
- stochastic investor-base redemption paths;
- investor-base composition changes;
- LMT threshold logic;
- swing pricing, gates or suspensions;
- price impact;
- second-round redemptions;
- macroprudential contagion;
- repo financing;
- counterparty exposure;
- collateral haircuts;
- margin calls;
- new portfolio construction logic.

## Important design decision

The TTL tab should be **scenario-independent** in this first version.

It should answer:

&gt; Given the current portfolio, how many business days are needed to raise cash for benchmark redemption shocks under different participation-rate and liquidity-haircut assumptions?

It should **not** answer:

&gt; What is TTL under the dashboard’s selected market scenario and investor-redemption path?

That richer link can be added later, but it is not part of this ticket.
